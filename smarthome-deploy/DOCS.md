# SmartHome Deploy — версия 0.3.0 (только чтение)

Приложение Home Assistant OS для просмотра расхождений между управляемыми файлами Home Assistant и приватным репозиторием GitHub.

## Установка с телефона

1. В Home Assistant откройте **Настройки → Приложения → Магазин приложений** (в некоторых версиях: **Настройки → Дополнения → Магазин дополнений**).
2. В меню **⋮ → Репозитории** добавьте **https://github.com/PheronIIx/SmartHome-HAOS-Apps**.
3. Обновите магазин и найдите **SmartHome Deploy (read-only preview)**.
4. До установки создайте резервную копию HAOS через штатный интерфейс и убедитесь, что есть доступ к Proxmox для восстановления.
5. Установите приложение, но перед первым запуском настройте его:
   - `repository`: `PheronIIx/SmartHome`;
   - `branch`: `main`;
   - `github_token`: fine-grained GitHub PAT с доступом **только к PheronIIx/SmartHome**, разрешение **Contents: Read-only**. Токен вводится только в настройках приложения.
6. Запустите приложение и откройте его веб-интерфейс через **Открыть веб-интерфейс**. Нажмите **Проверить**.
7. Сверьте результаты с текущими файлами; при ошибке используйте **Журнал** приложения, но не передавайте токен в переписку.

## Безопасность

- Доступ к домашней конфигурации в контейнере: `homeassistant_config` с `read_only: true`.
- Отсутствуют операции записи и API установки; сервер отвечает только на GET, POST отклоняется.
- Приложение не запускает службы HA, Proxmox, Frigate и не изменяет дашборды.
- Веб-интерфейс через Ingress, без публикации пользовательского сетевого порта.
- `panel_admin: true` скрывает боковую панель от неадминистраторов, но **сам по себе не является полноценной серверной авторизацией**; до разработки действий установки понадобится отдельная схема проверки прав.
- Версия 0.1.0 проверена на реальной HAOS: сборка, Ingress, подключение к приватному GitHub и сравнение выполнялись. **Новые функции 0.2.1 ещё не проверены на HAOS.**

## Что сравнивается

Ветка `main` приватного репозитория содержит источники в `home-assistant/`. Из неё учитываются:
- `configuration.yaml`, `automations.yaml`, `scripts.yaml`, `scenes.yaml`;
- `packages/*.yaml`;
- `www/*.js`;
- `www/plans/*.json`.

Версия **0.2.1**: для статусов «Изменён» и «Отсутствует» появляется кнопка **«Различия»**. По нажатию приложение отдельно получает из GitHub файл строго из коммита, показанного вверху, и строит unified diff: строки с `-` — текущий Home Assistant, строки с `+` — GitHub. Различия только в CRLF/LF и финальных переводах строк отмечаются отдельно. Максимум 256 КиБ на каждый файл и 2500 строк diff; большие файлы не раскрываются целиком. Данные для сравнения доступны в браузере только через Ingress. Содержимое разрешённых файлов может включать чувствительную локальную информацию: не публикуйте скриншоты diff с адресами/ключами без проверки. Изменения устанавливать по-прежнему нельзя.

Приложение показывает статусы `same`, `modified`, `missing`, `error` для файлов, имеющихся в GitHub. Сравнение основано на Git blob SHA-1 точного зафиксированного коммита; это побайтовое сравнение, а не YAML-валидация.

Исключены `secrets.yaml`, `.storage`, `ssh/`, `docs/`, `frigate/` и `dashboards/server.yaml`. Этот MVP не исследует лишние файлы на HA.

## Разработка и проверки

`PYTHONPATH=. python -m unittest discover -s tests -v` — тесты сравнения, в том числе проверка путей и отсутствующего токена.

Этот отдельный публичный репозиторий **не содержит** домашние конфигурации, токены или ключи. Изменения в нём публикуются независимо от приватного `PheronIIx/SmartHome`.

Код проекта: [публичный репозиторий](https://github.com/PheronIIx/SmartHome-HAOS-Apps). Архитектура и будущий механизм развёртывания хранятся в приватном SmartHome.

## Формат строк и классификация в 0.2.1

При общей проверке для файлов, отличающихся по байтам, приложение дополнительно сравнивает текст с нормализацией CRLF/LF и завершающих переводов строки. Статус `format_only` означает, что содержимое идентично после такой нормализации. Статус `modified` означает реальное отличие содержимого. Статус `unclassified` означает, что дополнительная диагностика не выполнена (например, лимит 256 КиБ или ошибка GitHub); это не доказательство изменения содержимого. Текущий файл на HA не изменяется.

Для `format_only` на кнопке «Различия» показывается только пояснение с CRLF и завершающими переносами, без огромного diff. Для `modified` diff игнорирует CRLF/LF, но не игнорирует изменения пробелов или содержимого.

## 0.3.0 — подготовка установки без записи

Добавлена кнопка **«Подготовить план»**. Укажите `baseline_commit` — SHA подтверждённой исходной версии файлов. Для первого испытания по совместно проверенным 15 файлам используется `8de108c40d4ffd0f10039fe4e7e9eec047494974`. Это **базовый ориентир для сравнения**, а не отметка о реальной установке: идентичность была подтверждена по содержимому с допуском CRLF/LF.

Приложение сравнивает список разрешённых файлов в базовом коммите с целевым коммитом ветки `main`, проверяя локальные файлы относительно базовой версии. Возможные исходы:
- `no_change` — в GitHub файл не менялся относительно базы, локальная версия ей соответствует;
- `candidate_review` — GitHub отличается от базы, локальный файл базе соответствует; требуется ручной просмотр и подтверждение;
- `blocked_local_drift` — локальное содержимое отличается от базы, отсутствует либо не удалось надёжно сверить; **запрещать будущую установку до разбора**;
- `new_file_review`, `deletion_review` — новые или удалённые в GitHub файлы требуют отдельного согласования.

Сверка только для файлов размером до 256 КиБ; превышение лимита блокирует уверенное заключение. Никакого деплоя, бэкапа или отката в версии 0.3.0 ещё нет. Информация о планируемых изменениях **не является** автоматическим разрешением на установку. Не менять baseline_commit автоматически после PR: для последующих установок потребуется модель проверенной установленной версии и журнал.
