# SmartHome HAOS Apps

Публичный репозиторий **кода приложений** для частного умного дома. Конфигурации домов, секреты и другие персональные данные здесь не хранятся.

## Установка репозитория

Home Assistant → Настройки → Приложения → Магазин приложений → ⋮ → Репозитории:

```
https://github.com/PheronIIx/SmartHome-HAOS-Apps
```

`smarthome-deploy` развивается поэтапно: 0.6.0 проверена на HAOS для одного строго ограниченного тестового файла; 0.7.0 добавила per-file manifest и read-only план синхронизации; 0.7.1 исправила allowlist и резервирование; 0.7.2 отделяет форматирование от изменений содержимого; 0.8.0 добавила read-only проверку многофайлового набора; 0.9.0 добавляет внутреннее JS-only транзакционное ядро, ещё не доступное через UI/API. Полноценная многофайловая установка ещё не реализована.

Описание настройки: [SmartHome Deploy](smarthome-deploy/DOCS.md).

Статус: **0.7.1 установлена на HAOS; создание резервной копии и тестовое восстановление 15 файлов подтверждены пользователем. 0.7.2 проверена на HAOS (0 обновлений, 1 только форматирование); 0.8.0 готовится к проверке CI и на HAOS. Многофайловая установка не реализована.**


## 1.0.0-rc.1 — кандидат в релиз JS Deploy (PR #16)

Кандидат в релиз добавляет к внутреннему ядру 0.9.0 минимальные Ingress API и UI: подготовка краткоживущего плана, установка по отдельному подтверждению, история операций и ручной откат. Опция `enable_multifile_install` **по умолчанию выключена**. Старый `enable_test_install` действует отдельно.

Ограничения ядра сохраняются: обновление существующих и добавление новых отсутствующих `www/*.js` из явного allowlist, максимум пять файлов, никакого YAML/JSON, удалений или локальных конфликтов. План привязан к коммиту и SHA-256 файлов; перед записью ядро повторяет проверки и создаёт проверяемый ZIP. При ошибке выполняется попытка отката; если она не подтверждена, последующие установки блокируются. Архивы приложения не заменяют полный бэкап HAOS.

**Статус:** PR, не объединено и не проверено на рабочем HAOS. Тесты CI и ревью безопасности необходимы до испытаний. Включать тестовый режим и устанавливать JS без отдельного согласования процедуры нельзя. Интеграция с дашбордом «Сервер» — отдельный этап.

**Условия стабильной 1.0.0:** завершённое ревью безопасного доступа к Ingress, успешный CI, полный бэкап HAOS перед записью, проверенные на HAOS установка нового JS, обновление существующего JS и откат обоих сценариев, подтверждение корректности манифеста и журнала. До этого `1.0.0` не выпускается; `rc.1` не объявляется проверенной стабильной версией.

**Доступ в 1.0.0-rc.1:** согласовано использовать штатную модель Home Assistant: `panel_admin: true`, вход только через Ingress, без ручных списков ID. Приложение не проверяет роль пользователя отдельно на каждом API-запросе — ограничение и проверка неадминистраторского доступа на реальном HAOS остаются условием приёмки. Новая ролевая модель — отдельная задача INF-04.

## 1.0.0-rc.3 — DEV-07, единая система обновлений (PR #17)

Ветка PR #17 содержит согласованный серверный allowlist только для `www/smarthome-updates.js`, автоматический **read-only** опрос при старте add-on и далее каждые 6 часов. Планировщик формирует локальный JSON `/config/.smarthome-deploy/status.json` с последним закреплённым SHA, временем проверки, JS-кандидатами, блокировками и ошибками. Публикация атомарная, ошибка не маскируется нулём. Установка изменений остаётся строго ручной, `enable_multifile_install=false` по умолчанию.

Связанный [SmartHome PR #12](https://github.com/PheronIIx/SmartHome/pull/12) добавляет `sensor.smarthome_deploy_updates`, расширяет единый `sensor.infra_updates` и использует общий `custom:smarthome-updates-card` на «Дома» и «Сервер». Карточка не вызывает install API. `packages/infra.yaml` переносится **вручную** через HA File Editor; Storage-панели меняются только через интерфейс HA, не через Deploy. Не расширяем JS-only allowlist на YAML, JSON и `.storage`.

**Фактический статус:** пользователь подтвердил установку на HAOS только `1.0.0-rc.1` с проверкой read-only/архива. DEV-07 и `rc.3` пока только в GitHub PR, в HAOS не установлены. Первая реальная установка нового JS, обновление существующего JS и откат остаются непроверенными. Не объявлять `1.0.0` стабильной до отдельно согласованной процедуры с полным бэкапом и проверкой отката. Подробности — [DOCS.md](smarthome-deploy/DOCS.md).
